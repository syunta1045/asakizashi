## P0 — v1.0.3 で直す（実ユーザー全員に見える）

### 1. birthDateProvided 3連バグ（後入力の袋小路）★最重要
- **後入力が死んでいる**: `/edit/birth`（app/edit/[field].tsx:103 付近）は birthYear/Month/Day の setField と computePillars() しか呼ばず `birthDateProvided` を true にしない。computePillars は `!birthDateProvided` で早期 return（lib/store.ts:86-89）。→ chart.tsx:46「生年月日を入力する」→入力→**まだロック**の無限ループ。オンボは name→wake-up→themes の3ステップで誕生日を聞かないため、**v1.0.2 の全新規ユーザーが傾向メモ等を永久に解錠できない**。
- **sync 復元欠落**: lib/sync.ts:38-52 dbToProfile が birthDateProvided を復元しない（DBにカラムも無い）。機種変更→pull で入力済みユーザーの命式が消える。逆に profileToDb はスキップユーザーでもダミー birth_date（1998-07-12）を実値として送信（sync.ts:21）。
- **ダミー表示**: app/settings.tsx:173 が未入力ユーザーに「1998年7月12日」を実データのように表示（profile.tsx:25 は正しく「未入力（任意）」分岐）。

**Fix**: ①BirthEditor の onYear/onMonth/onDay（＋clamp useEffect）で `setField("birthDateProvided", true)` を computePillars 前に呼ぶ。②pull 時に `birthDateProvided: (data.day_pillar ?? "") !== ""` を復元（恒久対応は birth_date_provided カラム追加＋未入力時 null 送信）。③settings を profile と同じ分岐に。④「スキップ→後入力→pillars非null」「push→pull往復でpillars維持」のテスト追加。

### 2. 今日の干支がUTC計算 — JST 0時〜9時は「前日」の朝メモ
app/(tabs)/today.tsx:39 と app/(tabs)/pace.tsx:16 が `dayPillar(new Date())`、dayPillar は getUTC* を使用（lib/bazi.ts:121-127）。**朝アプリの核となる起床直後の時間帯に前日の内容が出て、9:00 に突然切り替わる**。lib/interpretation.ts:143 のモックシードもローカル isoDate() と UTC 由来が混在。

**Fix**: `function todayForPillar(){ const n=new Date(); return new Date(Date.UTC(n.getFullYear(), n.getMonth(), n.getDate())); }` を作り、2箇所の `dayPillar(new Date())` を置換。dayPillar 本体は誕生日計算が依存するため触らない。

### 3. streak が「今日未記入」で0表示 — 毎朝リセットに見える
lib/journal.ts:66-80 getStreak は i=0（今日）にエントリが無いと即 break。振り返りは夜に書く設計なので、**100日ユーザーでも毎朝〜夜まで today のバッジ消滅・journal「0日続けて記録しています」**。主要動機付けが毎朝壊れて見える。

**Fix**: `const start = entries[todayKey()] ? 0 : 1;` の猶予付きに。journal.tsx:30/36 の prevStreak/newStreak 比較の成立をテストで担保。

### 4. 承認済み Build 17 が master 未コミット（コード不要・今すぐ）
最終コミットは 5fe1119（Build 15）。1.0.2 の占い脱色改修（30ファイル）が working tree にしか存在しない。`git checkout .` 一発で承認コードが消え、Build 17 の再現が不能になる。

**Fix**: `release: v1.0.2 (Build 17, App Store承認 2026-07-02)` でコミット＋ `git tag v1.0.2-build17` → push。以後リリース毎にタグ。ビルド時 EXPO_PUBLIC_* のキー名一覧と EAS ビルドIDを CHANGELOG に記録。

### 5. index.tsx が pillars を要求 — 未入力ユーザーは毎起動 welcome がちらつく
app/index.tsx:7 が `isOnboarded && pillars` を要求（_layout.tsx:91-93 は isOnboarded のみで正）。誕生日スキップユーザーはコールドスタート毎に /welcome を経由して /today に引き戻される。ちらつき＋その隙に「はじめる」を押すとオンボ再突入。

**Fix**: `if (isOnboarded) return <Redirect href="/today" />;` に変更、pillars 依存を削除。

### 6. 未入力ユーザーは「大切な人」登録済みでも登録促しカードが出続ける
app/(tabs)/today.tsx:94-101 dailyRelation が `pillars ? ... : null` でゲート。pickDailyRelation 自体はユーザー命式に依存しない。

**Fix**: 選出は `relations.length > 0` で行い、pillars 無しなら compat 抜きの汎用トーンでカードを組む。

## P1 — 収益・信頼（v1.1 で）

### 7. 課金者がオフラインで free に降格し得る
lib/revenuecat.ts:165 checkEntitlementState が catch で `{active:false}` を返し「エラー」と「非加入」を区別しない。_layout が起動/復帰毎に applyEntitlement → RC キャッシュ切れ＋圏外で課金者がプレミアム喪失。
**Fix**: 戻り値に `failed:true` を追加し、失敗時は applyEntitlement をスキップ（直前状態維持）。降格は「正常応答かつ inactive」のみ。

### 8. プレミアムの看板「4テーマ深掘り」が実質固定文 — 解約リスク
app/(tabs)/today.tsx:500 付近。「人間関係」「お金」の detail は日付・ユーザーに依らず完全固定。月¥480/年¥3,800 の継続対価として薄い。
**Fix（最小コストで最大）**: lib/journal.ts に moodTrend/moodByWeekday/moodSparkline/longestStreakInRange が**実装済み**→ 無料=直近7日、プレミアム=30/90日+曜日別+前週比の「見返り」画面を新設。深掘り本文は日柄シード×テーマで最低30パターン/テーマに拡充。

### 9. ペイウォールの過大表示 — 「通知時間の調整」の実態は夜の5択のみ
app/premium.tsx:33。朝通知は起床+10分固定で、起床時刻は無料で変更可能。有料でロックされているのは夜の時刻チップだけ。購入後の失望→返金・低評価の火種。PremiumLock のデフォルト文言「記録の見返しを広げます」も該当機能が存在しない。
**Fix**: 短期は文言を「夜の振り返りの時刻を選べます」に修正。中期は朝通知の分単位カスタム＋週末別時刻をプレミアム化すれば文言どおりになる。

### 10. 課金ファネル計測がほぼゼロ／PremiumLock は到達不能デッドコード
components/PremiumLock.tsx:15 の使用箇所は chart.tsx の1箇所のみで、そのゲート fiveElements は premium:false のため**絶対に表示されない**。purchase/restore 系 track はゼロ。
**Fix**: /premium 全導線に `track("premium_viewed", {source})`、premium.tsx に purchase_started/completed/failed/restore_completed。FEATURE_LOCKS を実ゲート3機能（deepThemes/relations/eveningTime）に整理。

### 11. 価格・トライアル文言がハードコード
app/premium.tsx:92,164。¥3,800/¥480/33%お得/7日間無料が直書きで offerings の priceString/introPrice を見ていない。Apple の一斉価格改定や再加入者（intro不適格）で表示と請求がズレる（2.3.1 リスク）。
**Fix**: getOfferings() から priceString を表示に使い、intro 適格性APIで「7日間無料」を出し分け。取得失敗時のみ現行文言。

### 12. リテンション装置の相互接続が無い
部品（streak/マイルストーン/通知）は揃っているが: 通知は毎日同一固定文、途切れ救済なし、マイルストーンが課金にも共有にも未接続。
**Fix**: ①途切れ翌朝の「おかえり」カード（最長n日→今日からまた1日目）②夜の保存時に翌朝通知へ streak 差し込み文で再スケジュール ③7日達成モーダル→30日見返し（プレミアム）へ接続 ④月1回の「繕い」無料付与＋無制限繕いをプレミアム特典に。

### 13. daily-message-batch Edge Function が無認証公開
supabase/functions/daily-message-batch/index.ts:79。no-verify-jwt 前提なのに認証チェックゼロ。第三者が連打すれば全ユーザーSELECT＋upsert コスト浪費、レスポンスにユーザー規模の概数も漏れる。
**Fix**: revenuecat-webhook と同じ `CRON_SECRET` Bearer＋constantTimeEqual 検証。

### 14. Google サインインの nonce が Math.random かつ未検証
lib/supabase.ts:136。予測可能な乱数で、signInWithIdToken に nonce を渡しておらず照合されない。
**Fix**: expo-crypto の randomUUID → SHA-256 を Google へ、生値を signInWithIdToken の nonce に。
